# デモデータ初期化

本番デモ前に、TSUNAGUの表示を毎回同じ状態へ戻すための管理機能です。通常の画面にはリンクを表示せず、許可された本部アカウントだけが `/demo-control` を直接開いて利用します。

## 有効化

フォーク先リポジトリの GitHub Environment `production` に、次の Variables を登録してデプロイします。

| 名前 | 例 | 用途 |
| --- | --- | --- |
| `DEMO_RESET_ENABLED` | `true` | 管理APIを有効化する |
| `DEMO_ADMIN_EMAILS_JSON` | `["demo-admin@example.com"]` | 実行を許可する本部メールアドレス |

許可メールは `HQ_EMAILS_JSON` にも含めてください。有効化後のURLは、本番URLの末尾に `/demo-control` を付けたものです。

## 安全策

- HQログインに加え、専用のメール許可リストを確認する
- CSRFトークンがない変更リクエストを拒否する
- 固定の確認文、確認チェック、ブラウザ確認の3操作を要求する
- リセットと再投入を1トランザクションで実行し、失敗時は元のデータへ戻す
- 実行者、成否、実行時刻、投入件数をアプリケーションログへ記録する
- 権限のないHQには管理APIの存在を示さず404を返す

## 初期化される内容

避難所、通常報告、インシデント状態、LoRa受信ログを削除し、固定の3避難所、通常報告、LoRa報告、要対応インシデントを再投入します。スマートフォンやPCのブラウザ内にある未送信キューは削除されません。

## デモ前の確認

1. 各デモ端末の未送信件数を0にする
2. LoRaゲートウェイの保留データがないことを確認する
3. `/demo-control` で初期化する
4. ダッシュボード、インシデント、タイムラインを確認する
5. デモ終了後は `DEMO_RESET_ENABLED=false` にして再デプロイする

本番へのデプロイ自体がデータを初期化することはありません。初期化は管理画面から明示的に実行した場合だけ行われます。
